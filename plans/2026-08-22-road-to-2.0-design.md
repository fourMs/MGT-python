# The road to 2.0: clearing the open issue backlog

**Status:** design, approved 2026-08-22. Implementation plans are written per track, not for this document as a whole.

**Goal:** Close the eight open issues in an order set by the breaking-change window, so that 2.0 is a small, shippable release rather than an open-ended one, and the JOSS submission has a stable API to be reviewed against.

**Scope note:** this is not one project. The eight issues are four unrelated tracks that share no code, and each substantive one needs its own spec and plan. This document decides the order and the release gates; it does not design any of the four tracks.

---

## The four tracks

| track | issues | nature |
|---|---|---|
| API hygiene | #346, #350 | renames and typing; the only genuinely breaking work |
| Publication | #311 | writing, not code |
| Research ports | #355, #357, #358, #359 | move working code from three studies into the toolbox |
| Architecture | #312 | in-memory pipeline; restructures how every method chains |

## The decision

**2.0 is API hygiene only. The in-memory pipeline (#312) lands additively afterwards and never takes a major bump.**

Two alternatives were considered. A *full 2.0* including #312 is the honest moment to change how every method chains, but #312 is a 2023 sketch with no design, it touches every processing method, and it would hold the release open indefinitely. A *small 2.0* that defers #312 without deciding its shape leaves the proposal unanswered for a third year.

The staged option was chosen because nothing about #312's value---skipping intermediate disk writes---requires breaking anything. An opt-in lazy pipeline beside the existing disk-writing one delivers the same benefit additively. Making it breaking buys nothing and costs the release date.

This keeps 2.0 small on purpose: the only actually-breaking item in it is the removal of one deprecated property.

## Track 1: API hygiene (blocks 2.0)

### #346 --- result-attribute naming

**Current state.** `ssm_figure` is canonical as of 9ef2a4f, with `ssm_fig` kept as a deprecated property alias; that commit also established the alias pattern the rest should follow. Two earlier renames (`subtract_video`, `sonomotiongram_audio`) landed in 744169f as part of a bug fix.

**What remains, split by stake.** `show(key=...)` resolves results by attribute name out of the instance dictionary, so anything it reads is user-reachable and renaming it is a real breaking change. It currently reads eleven attributes, and after 9ef2a4f exactly one of them is still an outlier:

- **User-reachable, needs a deprecation alias:** `motion_plot`.
- **Not reachable through `show()`, cosmetic:** `ssm_combined`, `pixelarray`, `motiongram_x`/`motiongram_y`, `videogram_x`/`videogram_y`.

**Done means.** Every stashed result ends in `_video`, `_image`, `_figure` or `_audio`. Each renamed attribute keeps a deprecated property alias, following 9ef2a4f: a property rather than a second attribute, because two plain attributes drift apart the moment either side is reassigned, and the getter re-raises under the name that was asked for so `hasattr` stays honest.

**Note on the `motiongram_x`/`_y` pair.** These are not simply misnamed. `_show.py` already carries an axis-alias vocabulary (`mgh`/`mgv` canonical, `mgx`/`mgy` legacy) because horizontal and vertical were historically confused with x and y. Renaming the attributes has to reuse that vocabulary rather than invent a third naming, or the confusion the aliases exist to fix returns.

### #350 --- internal typing

**Current state, measured 2026-08-22 against 9ef2a4f.** `mypy musicalgestures/` reports **248 errors in 32 files** (checked 71 source files). The issue's figure of ~301 is stale; the backlog has come down by roughly a sixth since it was written.

The distribution is the useful part. Five files carry 172 of the 248, or 69 per cent:

| file | errors |
|---|---|
| `_video.py` | 47 |
| `_utils.py` | 36 |
| `_360video.py` | 34 |
| `_audio.py` | 28 |
| `_cropvideo.py` | 27 |

By error code: `misc` 44, `arg-type` 42, `return-value` 32, `no-any-return` 31, `assignment` 30, `name-defined` 27, `union-attr` 23, with a small tail.

**One finding worth recording, because it looks like a bug and is not.** The 27 `name-defined` errors are artefacts of the `follow_imports=skip` setting in `[tool.mypy]`, not latent bugs. They were checked: `_cropvideo.py:228` reports `w`, `h`, `x`, `y` undefined on the very line that assigns them, and `ref_point` is a name the mouse-callback path sets. Nobody should spend time chasing these as defects, and a curated allowlist is the right treatment rather than code changes.

**Done means.** Zero errors on the five hot files, then a decision on the tail: either zero everywhere, or a curated per-code allowlist covering the `follow_imports=skip` artefacts. Then `|| true` comes off `mypy musicalgestures/` in `.github/workflows/ci.yml:87`, and the noxfile `typecheck` session gates merges.

**Sequencing constraint.** Type the five hot files *before* the #346 renames touch them, not after. `_video.py` and `_audio.py` appear in both lists, and typing a file whose attribute names are about to change means doing the reading twice.

### The 2.0 release itself

The breaking release removes the deprecated aliases introduced during preparation: `ssm_fig`, `motion_plot`'s alias, and any others added along the way. Nothing else in 2.0 is breaking.

## Track 2: #311 JOSS submission

**Current state.** `paper/paper.md` is a 48-line stub dated 26 August 2020, listing four authors, with `paper.bib` and two figures beside it. The 2023 comment on the issue lists the JOSS requirements and they are unchanged.

**Why it sits after 2.0.** JOSS review examines documentation, tests, and API stability, and a reviewer who arrives mid-rename sees churn. Submitting against a released, typed, blocking-CI 2.0 is a materially stronger submission for the same writing effort.

**Done means.** Author list refreshed against the actual contributor history, statement of need rewritten for what the toolbox is now rather than in 2020, figures regenerated from a current release, and the submission opened.

**Not decided here.** Authorship is not a technical question and belongs to ARJ.

## Track 3: research ports (after 2.0, into the new API)

All four issues say "port from study X". The source material was located and verified on 2026-08-22, and readiness differs far more than the issue text suggests. Order is by readiness, easiest first.

### #355 --- multi-view pose fusion. Highest readiness.

`2-Westney-comparisons/code/concert_fuse3d.py` and `reh_fuse3d.py` are **82 lines each and differ by exactly one line**: a hardcoded `PIECES` list. The issue's description of them as near-duplicates that should become one library function is exact, and the parameterisation is already obvious---the differing line is the parameter.

Umeyama similarity transform on rigid torso landmarks, plus 2D-visibility-weighted averaging, reporting cross-view residual in millimetres as a quality metric.

### #357 --- recurrence quantification. Good readiness.

Working implementation in `1-Still standing/v7-stillstanding-claude/deposit/_analysis/reports/57-which-descriptors-measure-the-body/scripts/spatiotemporal.py`, with a second copy under `reports/20-nothing-that-correlation-missed/scripts/`. The issue is right that it is bound to that study's loaders, so this is extraction rather than copying: recurrence rate and determinism on sway trajectories, plus sway-axis rotation and heading persistence, into `_posture`, with synthetic known-answer tests as done for SDA/DFA/SampEn.

### #358 --- effective DOF and segmental coupling. Good readiness.

Working implementation in `1-Still standing/v7-stillstanding-claude/deposit/_analysis/reports/01-identity-in-standstill/scripts/extract_coordination.py`. The issue flagged it as "borderline-general" and needing a full read before porting; that judgement still stands and is the first task of its plan, not a formality.

### #359 --- YOLO pose wrapper. Lowest readiness, despite appearances.

**Only the outputs survive.** `2-cymbal-comparison/paper-cymbals/` holds `timing_summary_yolo.json` and two figures, and the code that produced them is not in the tree. This is therefore written from scratch against Ultralytics, not ported, and it additionally needs a new optional dependency and a model-weights story. The surviving JSON is still valuable: it is a fixture the new wrapper can be checked against.

**Common constraint for all four.** Each lands behind the same trajectory-array contract as `extract_pose_landmarks`, so the `anchor_and_match`/`offset_stats` tooling can compare detectors on a shared clock.

## Track 4: #312 in-memory pipeline (own spec cycle, additive)

**Current state.** No `read`/`load`/`write` methods and no in-memory path on `MgVideo`; every preprocessing step writes a file and the next step reads it.

**Shape decided here, design deferred.** It is opt-in and additive. The existing disk-writing behaviour stays the default and keeps working unchanged. This is what removes it from the 2.0 critical path.

**Open, and genuinely open.** Whether the opt-in is a constructor flag, a context manager, or a separate lazy object; how memory is bounded for long videos, which is the reason the current design writes to disk at all; and whether the 2023 proposal's `read`/`load`/`write` triple is still the right surface. The issue is nearly three years old and the toolbox has changed a great deal around it, so its own brainstorming cycle should start by asking whether the proposal is still wanted before asking how to build it.

## Order and gates

1. **2.0 prep, part 1:** #350 on the five hot files. Before the renames touch them.
2. **2.0 prep, part 2:** #346 remaining renames, each with a deprecation alias.
3. **2.0 prep, part 3:** #350 tail decision; drop `|| true` in CI.
4. **2.0:** remove the deprecated aliases. Release.
5. **#311:** JOSS submission against 2.0.
6. **2.1+:** ports in order #355, #357, #358, #359.
7. **Separate cycle:** #312, starting with whether it is still wanted.

## Non-goals

- Redesigning `show()`. Its axis-alias vocabulary is reused by #346, not replaced.
- Chasing the `name-defined` mypy errors as defects. They are configuration artefacts.
- Porting #359 as a port. There is nothing to port; it is new code.
- Deciding JOSS authorship.

## Risks

- **The renames and the typing overlap.** `_video.py` and `_audio.py` are in both lists. Mitigated by ordering typing first; if that ordering slips, the reading is done twice.
- **The ports may not generalise.** #358 was flagged borderline-general by its own survey. A port that turns out to be study-specific should be closed as such rather than shipped as a general measure.
- **CI matrix breadth.** The last two releases both had Windows-specific CI failures that local Linux runs did not catch. Anything in this plan is verified on the matrix, not locally.
